# ADR-002: 抽選の状態をブラウザの localStorage に保存する

> **Status**: Accepted
> **Date**: 2026-10-23
> **Deciders**: プロジェクトオーナー
> **Consulted**: Claude

## 文脈（Context）

当日は主催者の PC 1 台で抽選を進める（ADR-001）。途中でページを再読み込みしたり、誤ってタブを閉じたりすると、それまでに出た番号が消えてゲームを続けられなくなる。
「リロードしても大丈夫なようにしたい」という要望（BIZ-BINGO-04）が出たため、保存先を決める。ADR-001 でサーバ・DB は持たないと決めている。

## 検討した選択肢

### 選択肢 A: localStorage に保存する
- **概要**: 番号の設定と出た番号（順番つき）をブラウザの localStorage に JSON で保存し、ページを開いたときに復元する
- **影響ファイル数の概算**: 1（試作 `prototype/display-compare.html` で実装済み）
- **撤回・ロールバック容易性**: 容易
- **既存 lessons.md / ADR との整合**: 整合（ADR-001 のサーバなしの方針どおり）
- **利点**: 依存なし。タブを閉じても、同じ PC・同じブラウザなら残る
- **欠点**: 別の PC やブラウザには引き継げない。ブラウザのデータを消すと消える

### 選択肢 B: sessionStorage に保存する
- **概要**: タブ単位で保存する
- **影響ファイル数の概算**: 1
- **撤回・ロールバック容易性**: 容易
- **既存 lessons.md / ADR との整合**: 整合
- **利点**: 依存なし
- **欠点**: タブを閉じると消えるため、誤って閉じたときに守れない

### 選択肢 C: 保存しない
- **概要**: 現状のまま
- **影響ファイル数の概算**: 0
- **撤回・ロールバック容易性**: 容易
- **既存 lessons.md / ADR との整合**: 整合
- **利点**: 作る量が増えない
- **欠点**: リロードでゲームが消える。要望を満たさない

## 決定（Decision）

選択: **選択肢 A**

**理由**:
リロードだけでなく、タブを誤って閉じた場合も続きから再開できるため。サーバを持たない方針（ADR-001）のまま実現できる。

## 影響（Consequences）

### ポジティブ
- リロード・タブの閉じ直しで、出た番号と設定が消えない
- 抽選した番号は演出の前に保存するので、演出中にリロードしても引き直し（やり直しによる番号の変更）にならない

### ネガティブ（受け入れるコスト）
- 保存できない環境（プライベートブラウズ等）では保存せずに動く
- 保存データが壊れていた場合は読み込まず、新しいゲームとして始める
- 「リセット」と「番号の設定変更」で出た番号が消えるため、確認を挟む

### 注意点
- GitHub Pages では同じアカウントの全リポジトリが同じオリジン（`<アカウント>.github.io`）を共有し、localStorage も共有される。保存キーには名前空間を付ける（試作: `bingo/prototype/display-compare/v1`）

### 追跡が必要な後続タスク
- [ ] 本実装の保存キーと、保存データの形式（バージョン番号を含む）を spec で決める
