# Lessons Learned（学習記録）

> 過去の失敗・発見・設計判断から学び、同じミスを繰り返さないための記録。
> セッション開始時に読み込み、記載された教訓を適用すること。

## 記録ルール

- 各エントリは `### YYYY-MM-DD: 簡潔なタイトル` 形式で追記する
- **原因**（なぜ起きたか）と**対策**（今後どうするか）を必ず含める
- 解決済み・陳腐化したエントリには `[RESOLVED]` を付与する

## 追記すべきケース

- 仕様整理で A/B/C 案を提示し、ユーザーが選んだ（設計判断）
- 一度決めた仕様を覆した（理由を残す）
- 仕様書どうし、または仕様書と実装の矛盾を見つけた
- ライブラリ・ホスティングの意外な挙動に遭遇した

## 仕様整理

### 2026-10-23: Q3（参加者カード）で A 案を採用

**原因**: 1か月以内・対面・主催者 PC からモニターに映す、という条件で参加者カードの扱いを A/B/C 案で提示し、A（紙のカード、アプリは抽選画面だけ）が選ばれた（ADR-001）。

**対策**: 参加者側の画面は作らない。参加者のスマホを使う要望が出たら、実装より先に ADR-001 を置き換える ADR を起票する。

### 2026-10-23: Q7-1（抽選機）でガラガラの 2D アニメを採用

**原因**: 抽選機の種類をガラガラ / ドーム型ビンゴマシン / 3D の 3 案で提示し、ガラガラが選ばれた。

**対策**: 3D ライブラリは使わない前提で考える。見た目の要望が 3D 寄りに変わったら、依存の追加として ADR を先に起票する。

### 2026-10-23: 回答が論点番号とずれて届くことがある

**原因**: Q3（参加者カード）への回答として、抽選の演出と番号設定の要望が届いた。論点の番号より、やりたいことから話が出やすい。

**対策**: 受け取った内容は該当する論点（Q5・Q6 など）に振り分けて記録し、元の論点は改めて確認する。

## 公開・デプロイ

### 2026-10-23: GitHub Pages では localStorage が全リポジトリで共有される

**原因**: GitHub Pages のプロジェクトサイトは `<アカウント>.github.io/<リポジトリ>/` で配信され、同じアカウントの全リポジトリが同じオリジンになる。localStorage はオリジン単位なので、他のリポジトリのページと保存領域を共有する。

**対策**: 保存キーには `bingo/...` のように名前空間とバージョンを付ける（ADR-002）。
